# Рекомендации по улучшению UI/UX бота

## 1. Мастер добавления речи (/add)

**Проблема:** Много шагов подряд без индикатора прогресса; пользователь не знает, что можно отменить.

**Рекомендации:**
- Показывать прогресс: «Шаг 1 из 7: Введите дату…»
- В первом сообщении писать: «В любой момент можно отменить: /cancel»
- После выбора общины кратко напоминать контекст: «Община: Жлобинчанка. Введите дату…»

**Статус:** Внедрено (подсказка /cancel, прогресс «Шаг X из Y»).

---

## 2. Длинные сообщения (лимит 4096 символов)

**Проблема:** /list и /stats при большом количестве записей могут превысить лимит Telegram.

**Рекомендации:**
- Разбивать длинный список предстоящих речей (/list) на несколько сообщений (как уже сделано для /plans).
- Разбивать длинную статистику (/stats) на части при необходимости.

**Статус:** Внедрено (splitMessage для /list, /stats, /plans).

---

## 3. Редактирование речи (/edit)

**Проблема:** Нужно вручную вводить ID и название поля (date, song, title…), легко ошибиться.

**Рекомендации:**
- Выбор речи по кнопкам: сначала дата (из списка предстоящих), затем выбор конкретной речи на эту дату.
- Inline-кнопки выбора поля: Дата, Песня, № речи, Докладчик, Телефон (название не редактируется — подставляется из списка при смене номера речи).
- После выбора поля запрашивать новое значение как сейчас.

**Статус:** Внедрено (выбор по дате и кнопкам; кнопки полей без «Название»; при смене № речи название берётся из БД).

---

## 4. Единообразие формулировок

**Проблема:** Разные подписи к одному и тому же действию («Выберите общину» vs «Выберите общину для просмотра списка речей»).

**Рекомендации:**
- Короткие универсальные фразы: «Выберите общину» для всех экранов выбора общины.
- Единый стиль пустых состояний: «Пока ничего нет. Добавить: /add» или «Добавить: /add_plan».

**Статус:** Внедрено (единые формулировки «Выберите общину», пустые состояния с подсказкой /add).

---

## 5. Подтверждение после успешных действий

**Сейчас:** Есть «✅ Речь добавлена», «✅ Речь #N удалена» — хорошо.

**Рекомендации:**
- В ответе после добавления речи можно добавить: «Посмотреть список: /list».
- После добавления пунктов в список речей: «Посмотреть список: /plans».

**Статус:** Внедрено («Посмотреть список: /list» после добавления речи, «Посмотреть: /plans» после add_plan).

---

## 6. Справка /help

**Проблема:** Длинный текст, все команды в одном блоке.

**Рекомендации:**
- Разбить на блоки: «Речи», «Список речей», «Общины», «Админ» — с краткими подписями.
- Или оставить одну справку, но сократить формулировки и добавить в конец: «В любой пошаговой операции: /cancel — отмена.»

**Статус:** Внедрено (блоки: Речи, Список речей, Общины, Админ; подсказка /cancel в конце).

---

## 7. Пустые состояния и подсказки

**Рекомендации:**
- «В общине X пока нет предстоящих речей» → добавить: «Добавить речь: /add».
- Редактирование речи без ID: выбор по дате и кнопкам (/edit).

**Статус:** Внедрено (пустые состояния с «Добавить: /add»; /edit — выбор даты и речи по кнопкам).

---

## 8. Быстрые действия (опционально)

**Идея:** Reply-клавиатура с кнопками [📋 Список речей] [➕ Добавить] [📊 Статистика] для быстрого доступа без ввода команд.

**Статус:** Внедрено (Reply-клавиатура после /start: [📋 Список речей] [➕ Добавить] [📊 Статистика]; кнопки вызывают те же действия, что и команды).

**Замечание:** Может занимать место в чате; при желании можно скрыть клавиатуру командой или не показывать по умолчанию.

---

## 9. Компактная статистика (/stats)

**Проблема:** Полный список тем в статистике был слишком длинным и превращался в «стену» текста.

**Решение:**
- В основном сообщении показывается краткая сводка (темы, проведений, последняя дата) и `ТОП-10` тем.
- Полный список показывается постранично (по 10 тем) через inline-кнопки «назад/далее».
- Добавлена отдельная выгрузка полного списка в XLSX, при этом матрица по годам (XLSX) сохранена.

**Статус:** Внедрено.

---

## Приоритет внедрения

1. **Высокий:** ✅ разбиение длинных сообщений в /list и /stats, прогресс и подсказка /cancel в /add.
2. **Средний:** ✅ кнопки выбора поля в /edit, единые формулировки, короткие подсказки после действий.
3. **Низкий:** ✅ разбитая справка /help, reply-клавиатура.
